# 中药学工具重构设计

## 目标

把原来偏应试、分散在 `data.js` 里的数据，升级成以药典原文为基础、以临床检索为核心的工具。系统保持轻量、可离线、页面干净，同时为后续知识图谱和 RAG 留出扩展空间。

## 数据架构

药典语料按条目拆分为 `data/pharmacopoeia.jsonl`，每行一个 JSON 对象：

```json
{
  "id": 479,
  "title": "黄芪",
  "pinyin": "Huɑngqi",
  "eTitle": "ASTRAGALI RADIX",
  "page": 368,
  "section": "药材和饮片",
  "type": "herb",
  "path": ["药材和饮片"],
  "text": "原始药典正文",
  "fields": [
    { "name": "概述", "text": "来源与采收加工" },
    { "name": "性味与归经", "text": "..." },
    { "name": "功能与主治", "text": "..." },
    { "name": "用法与用量", "text": "..." },
    { "name": "注意", "text": "..." }
  ]
}
```

条目类型：

- `herb`：药材和饮片。
- `extract`：植物油脂和提取物。
- `formula`：成方制剂和单味制剂。
- `index` / `front_matter` / `other`：索引、前言和其他条目。

后续扩展数据时，不要把新知识混进药典正文，应该继续保留分层：

1. `pharmacopoeia`：药典法定内容，作为安全底线。
2. `clinical_experience`：临床经验、医案、经典配伍，标注出处和证据级别。
3. `teaching`：教材分类、掌握级别、歌诀，只作为学习辅助。
4. `knowledge_graph`：药、症、方、医家之间的关系。

## 搜索设计

当前原型使用 Web Worker 在本地完成检索，避免服务端依赖，可直接部署到 GitHub Pages。

搜索权重：

- 标题精确匹配最高。
- 标题前缀、标题包含次之。
- 拼音和拉丁名。
- 章节、路径、字段名。
- 功能主治、用法用量、注意、正文全文。

界面分为四类：

- 全部。
- 药材饮片。
- 提取物。
- 成方制剂。

点击结果后打开详情抽屉，按药典原文的法定项目分段展示，避免长文一次性铺开。

## 页面结构

第一阶段保持极简三栏信息模型：

1. 顶部搜索框。
2. 分类筛选。
3. 结果卡片。

详情页采用抽屉式，展示：

- 基本信息：药名、拼音、拉丁名、页码、章节。
- 结构化项目：概述、性状、鉴别、检查、含量测定、性味与归经、功能与主治、用法与用量、注意、贮藏。
- 原始药典全文。

后续可在详情页追加独立模块：

- 临床要点。
- 常用剂量场景。
- 配伍与禁忌。
- 经典方剂。
- 关联症状。
- 学习记忆。

## 安全原则

- 剂量、毒性、配伍禁忌必须优先来自药典或权威标注来源。
- 无来源的经验数据只能进入“学习资料”，不得伪装成法定标准。
- 页面应始终保留免责声明：仅供学习研究，不作为处方依据。
- 所有 AI/RAG 输出都必须显示引用来源，并禁止生成未经验证的剂量。

## 后续路线

1. 补齐药典字段解析：把功能主治、剂量、注意进一步标准化。
2. 建立症状索引：咳嗽、失眠、痛经、便秘、水肿等常见主诉。
3. 引入经典方剂库：方名、组成、主治、出处、配伍逻辑。
4. 建立关系图谱：中药 - 症状 - 方剂 - 医家。
5. 加入结构化医案检索，而不是直接让模型自由生成。
6. 支持 PWA 离线缓存和移动端快查。
