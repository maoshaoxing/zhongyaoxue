# 药典临床检索 v2 改进方案

> 针对 `clinical/` 子应用的检索质量改进。所有结论均基于 2290 条真实数据实测，不是经验推测。

## 一、问题定位

用 Node 复现初版的 `matchScore / search`，在真实语料上跑基准，暴露出三类问题：

| 编号 | 问题 | 实测证据 |
|---|---|---|
| P0-1 | 拼音搜不到 | `huangqi` 只命中 2 条且**不含黄芪**；`huɑngqi`（含 U+0251）才 8 条含黄芪 |
| P0-2 | 每次按键全量重算 | `黄芪` 94ms、`麻黄 桂枝` 124ms（桌面 Node），手机约 300–500ms；且无 debounce |
| P0-3 | 多词排序倒挂 | `麻黄 桂枝` 排序：冯了性风湿跌打药酒 420 > 小青龙合剂 420 > **麻黄 294** |
| P1-4 | 索引条目污染结果 | `huangqi` 第 2 条是「汉语拼音索引」 |
| P1-5 | SW 缓存锁死更新 | `sw.js` 对所有 GET 用 cache-first，数据文件改了永远看不到 |
| P1-6 | 教材数据未接入 | `data.js` 里 348 味的掌握级别/四气五味/归经/歌诀，检索页一条没用 |
| P1-7 | 俗名对不上正名 | 教材 348 味中 38 味按名匹配不到药典条目 |

### P0-1 的成因

药典拼音用的是 **拉丁 alpha `ɑ`（U+0251）** 和 **script g `ɡ`（U+0261）**，不是普通 `a` / `g`：

```
huɑngqi  →  h u ɑ n g q i     ← 药典原文
huangqi  →  h u a n g q i     ← 用户输入
```

`normalize("NFKC")` 不做这个映射，所以 `includes` 永远 false。手机键盘上根本打不出 `ɑ`，等于该字段对用户不可用。

### P0-3 的成因

初版对多词查询的处理是「求和后统一乘折扣」：

```js
score = total * (zeroCount ? 0.15 : 1)
```

麻黄标题精确命中 1400 分，但因为「桂枝」未命中被整体 ×0.15 → 1960 × 0.15 = 294。
而一个药酒只要两个词各在 3 个字段里蹭到 → 210 + 210 = 420。
**标题完全一致，输给了正文里顺带提到。**

## 二、改动清单

### 检索核心 `clinical/search-worker.js`

| 改动 | 具体做法 |
|---|---|
| 归一化重写 | 先 `NFD` 去声调 → `NFKC` → 小写 → `ɑ→a`、`ɡ→g`、`ü→u`、`v→u`，去掉 `’ · •` 空格和标点 |
| 索引预计算 | 加载时把标题/基名/拼音/拉丁名/章节/各字段正文一次性 fold 存进 `entry._`，查询只做 `includes` |
| 拼音分级 | 精确 +900、前缀 +700、子串 +470（解决 `huangqi` 撞上 `huangqingwei`） |
| 字段命中截断 | 原按每个字段累加，长方剂靠字段数量刷分 → 改为 `min(字段名命中,3)×130 + min(正文命中,6)×75` |
| 排序重构 | 三级排序：**标题命中** > 全部 token 命中 > 总分（解决了标题精确匹配被压制） |
| 别名命中 | 反查表把俗名挂到正名条目上，命中 +900（全虫→全蝎、田七→三七、国老→甘草、元胡→延胡索） |
| 默认过滤 | `type` 为 `index / front_matter / other` 的条目不再进默认结果 |
| 新增筛选 | `filter=mastery` → 只看教材「掌握」级 |
| 失效代码移除 | 删掉永远不会触发的 `idx.all` 兜底（顺带省下一次 420 万字的 fold，加载从 651ms 降到 341ms） |

### 交互 `clinical/app.js`

- **debounce 140ms**：不再每个按键都全量检索
- **命中高亮**：单次正则替换，`<mark>` 标出匹配词（避免多次 replace 产生嵌套标签）
- **教材级别徽章**：掌握（红）/ 熟悉（黄）/ 了解（灰）
- **键盘可达**：卡片 `tabindex=0 role=button`，Enter / 空格打开
- **焦点管理**：打开抽屉聚焦关闭按钮，Esc 关闭后焦点回到原卡片
- **详情教材块**：掌握级别 / 教材分类 / 四气五味 / 归经 / 教材功效

### 缓存 `sw.js`

| 场景 | 策略 |
|---|---|
| 页面导航 | network-first（部署后立即看到新版） |
| `*.json` / `*.jsonl` | stale-while-revalidate（先给缓存，后台更新） |
| 静态资源 | cache-first |
| 预缓存 | 补入 `clinical/` 全部 5 个文件（此前子应用离线打不开） |

`CACHE_NAME` 提到 `v5-20261115`，激活时清理旧缓存。预缓存改为逐个 `cache.add().catch()`，单个资源失败不会让整个 install 失败。

### 新增数据

- `data/teaching.json`（63KB）：282 味的教材信息 + 76 条别名映射
- `scripts/build_teaching.mjs`：从 `data.js` + 药典语料重新生成，可随时跑

## 三、效果对比

| 指标 | 改前 | 改后 |
|---|---|---|
| 单次查询（桌面 Node） | 70–95ms | 4–10ms |
| 索引构建 | ~90ms（无索引） | 341ms（一次性） |
| `huangqi` 命中 | 2 条，黄芪不在 | 16 条，**黄芪第 1** |
| `麻黄 桂枝` 首位 | 冯了性风湿跌打药酒 | **麻黄** |
| `田七` | 0 条 | 三七（掌握） |
| `全虫` | 0 条 | 全蝎（掌握） |
| `国老` | 0 条 | 甘草（掌握） |
| `元胡` | 成药排在药材前 | 延胡索（元胡）第 1 |
| `竹叶` | 需要用户知道叫"淡竹叶" | 淡竹叶第 1 |

端到端实测（Edge 无头）：首屏 833ms 就绪、渲染 120 张卡片、搜「黄芪」产生 191 处高亮、教材块正常、Esc 正常关闭、无 JS 报错。

## 四、别名映射说明

`data/teaching.json` 的 `alias` 字段把四类名字统一挂到药典正名：

1. **人工对照表**（20 条）：全虫→全蝎、蚯蚓→地龙、田七→三七、白僵蚕→僵蚕、乌蛇→乌梢蛇、龟板→龟甲、团鱼甲→鳖甲、鸡肫皮→鸡内金、益智仁→益智、鲍鱼壳→石决明、珠母→珍珠母、白花蛇→蕲蛇、海蛤壳→蛤壳、竹叶→淡竹叶、贯众→绵马贯众、萆薢→粉萆薢、沙参→南沙参、瓜蒌根→天花粉、棕榈炭→棕榈、地鳖虫→土鳖虫
2. **教材 ALIAS_DATA**（49 条）：土元、国老、坤草、大力子、金铃子、破故纸…
3. **药典自带括号别名**（7 条）：从「土鳖虫（䗪虫）」「延胡索（元胡）」这类标题里自动抽取
4. **教材名 ≠ 药典名**（19 条）：上面第 1 类同时兼作此项

### 药典一部确实未收载的 11 味

白花蛇舌草、败酱草、臭梧桐、青木香、六神曲、神曲、南瓜子、苎麻根、竹沥、龙骨、浮小麦

这些搜不到属正常，需要在 UI 上给提示而不是空结果（见后续建议）。

## 五、未做的部分

按优先级排列，都可以继续做：

1. **URL 状态**：查询词与当前条目未同步到 `?q=` / `?id=`，刷新丢失、无法分享、安卓返回键不关抽屉
2. **"未收载"提示**：搜上述 11 味时给出「该品种药典一部未收载，教材归入 XXX」而不是「没有匹配」
3. **首屏体积**：`pharmacopoeia.jsonl` gzip 后 2.06MB。可拆成「轻索引（标题+拼音+功能主治）」+「详情按需拉取」，首屏能压到 300KB 以内
4. **IndexedDB 缓存**：数据只在内存，每次冷启动都要重新解析
5. **同义词扩展**：搜"拉肚子"找不到"泄泻"
6. **重复字段名**：黄芪的「性状/鉴别/含量测定」出现两次（药材与饮片规格各一组），可加副标题区分
7. **分页 / 无限滚动**：目前固定 120 条上限

## 六、如何重新生成数据

```bash
node scripts/build_teaching.mjs
```

会读取 `data.js` 与 `data/pharmacopoeia.jsonl`，输出 `data/teaching.json`。
改了教材 `data.js` 后记得重跑，否则教材徽章和别名不会更新。

## 七、如何回滚

本次改动集中在 4 个文件：`clinical/search-worker.js`、`clinical/app.js`、`clinical/style.css`、`sw.js`。
`git revert <commit>` 即可完整回退，新增的 `data/teaching.json` 与 `scripts/build_teaching.mjs` 是纯增量，不影响旧逻辑。
